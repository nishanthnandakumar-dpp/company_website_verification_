Historical data will fool you if you let it

A result that looks strong on past data has two possible explanations. Either you found something real, or you found a pattern that history produced by accident. Both look the same on the chart.

This is measured, not folklore. In 2016, McLean and Pontiff followed 97 published market predictors in the Journal of Finance. Tested outside the sample where each was discovered, the same predictors measured 26% weaker. After publication, 58% weaker.

McLean & PontiffJournal of Finance, 2016
doi.org/10.1111/jofi.12365

The mechanism is simple. The more variations of an idea you try, the more likely your most impressive result is the luckiest one rather than the best one. Bailey, Borwein, López de Prado and Zhu showed it plainly in the Notices of the American Mathematical Society in 2014: try enough, and an overfit result stops being bad luck and becomes the expected outcome.

Bailey, Borwein,
López de Prado & ZhuNotices of the AMS, 2014
doi.org/10.1090/noti1105

AI has made this faster. A model can now produce a plausible analysis, a clean explanation and well-formatted code in seconds, and every part of it can be wrong in ways that are hard to see. The output reads like work that was checked. Often nothing checked it.

Meanwhile decisions get made. Someone commits money, or capital, or a year of engineering, to a number that no one has actually verified. That is the problem we build against.

Verified, not assumed

So we built our work the other way round. Four rules, and they have cost us results we would have liked to keep.

01

Decisions before results

The test is written down and fingerprinted before the data is read: what counts as a pass, what counts as a failure, what would make us drop the idea entirely. Once a result exists, the rule cannot bend to fit it, because the rule was sealed first.

02

Reproducible results

The same inputs and the same code give the same answer. Every output records the exact version of the data and the code that produced it, so anyone can run it again and get the same thing, or find out why they did not.

03

Every test counted

If we try twenty ideas, the record says twenty. Nothing gets quietly dropped for looking unpromising. The more we have tried, the stronger the next result has to be before we believe it.

04

Fail-safe by design

When something is missing, uncertain, or does not match what we expected, the system stops and says why. It does not guess, fill the gap, or carry on with a best effort. Stopping is cheap. Acting on a wrong number is not.

What that looks like in practice

Principles are cheap to write. These come from the record.

Every run is written to a record that cannot be quietly changed.

Each run is appended to a hash-chained ledger, and the database itself refuses to let anything already written be altered or removed. If a number is questioned a year later, the chain either holds or it does not.

Why it matters: an auditor, a regulator or a colleague can check for themselves, without taking our word for it.

Our evaluations run alongside placebo versions built to find nothing.

If the method finds something where nothing exists, we know the method is broken before we trust anything it says.

Why it matters: a method that can never produce a negative isn't measuring anything.

Three kinds of work, one standard

That discipline is the product. It shows up in three kinds of work.

Quantitative research systems

Research infrastructure that turns a question into a measured answer: the test defined and sealed first, the statistical validation chosen in advance, the cost of acting on the answer modelled rather than assumed. The output is a record you can argue with, not a chart.

Data engineering and infrastructure

Pipelines and storage for financial time series, built so the data can be trusted later. Every input versioned and fingerprinted, every gap counted, every value traceable to where it came from. Verification happens before use, not after a surprise.

Auditable, AI-assisted software

We use AI where it genuinely helps, inside a loop that checks it. Generated analysis and code are validated against source data and tests before anything is accepted, and every step is written to a record a person can read, repeat and disagree with.

What we are building now

Two projects are in the workshop. Both run on the same rule as everything else here: nothing counts until it has been checked.

CIPHER In development

An autonomous decision engine for finance.

A general AI model can produce a thousand convincing ideas in a minute. CIPHER exists to find the one that survives.

It is not a chatbot and not a research tool. It is a private, purpose-built engine that generates ideas, tests them under rules it cannot change, and decides on its own what is real enough to act on. Everything else it throws away, and it keeps a record of what it threw away and why.

  • It cannot fool itself. Its rules are sealed before it sees a single result, and every idea runs against decoy versions built to find nothing.
  • It keeps its own exam. Part of its history stays locked away, untouched, so anything it believes is tested on data it has never seen.
  • It remembers every attempt. The more it tries, the harder it becomes to impress, so luck has nowhere to hide.
  • It stops instead of guessing. When something doesn't add up, it halts and explains why, rather than carrying on.
  • It answers to a permanent record. Every decision is written to a tamper-evident ledger that can be checked years later.

LONGVIEW Active research

The same engine, aimed at the long game.

LONGVIEW takes everything built for CIPHER and points it at patterns that unfold over months and years. It inherits the same sealed rules, the same decoys, the same untouched data and the same permanent record. What it adds is patience.

  • Every idea needs a reason. Nothing is tested unless there is a clear economic explanation for why it should exist.
  • Fewer ideas, longer histories. It studies a handful of ideas deeply instead of many quickly.
  • Built on CIPHER's failures. Everything CIPHER rejected sharpens what LONGVIEW tests from the start.

It is early, and it is in testing. We will say more when there is something verified to say.
